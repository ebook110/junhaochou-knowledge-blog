> **方法提示**：知识库的关键不是记录数量，而是未来的自己能否判断一条信息的来源、适用条件和新旧状态。

## 分类少而稳定，标签具体而克制

一级分类表达长期主题，例如 VPS、仿真或学习项目；标签表达文章中的具体对象，例如 `Docker`、`APDL`、`journalctl`。不要为每次临时想法创建新分类，也不要把整句摘要写成标签。

## 每篇文章写清“验证状态”

发布日期说明内容首次形成时间，更新时间说明正文修订，最后验证日期说明命令或流程最近一次在什么环境中确认过。三者分开，读者才不会误把旧经验当成当前结论。

```markdown title="文章 frontmatter 片段"
---
category: linux
tags: [systemd, 日志]
lastVerified: 2026-08-01
related: [linux-service-checklist]
---
```

## 系列承载“顺序”，相关文章承载“关联”

系列适合必须按顺序学习的流程，例如从 VPS 安全基线到容器部署；相关文章适合跨主题的补充阅读。两者不要互相替代，否则导航会变得难以预测。

## 每月一次轻量维护

每月检查失效链接、过期版本和未验证文章。将修订记录写进 Git 提交信息，把重要命令在受控环境复跑。长期维护靠的是小而连续的复核，不是一次性重写。
